# STL на Google Диске

Новые STL (одиночная и массовая загрузка) отправляются на Google Диск; Supabase хранит авторизацию, модели, счётчики и изображения. В `stl-models` новые обложки — только WebP 640×500, качество 0.82, до 2 МБ. Фото Makes и референсы стола заказов по-прежнему в `catalog-social`. Скачивание обложки пользователем остаётся PNG. Расчёт технических параметров, собственное фото и ползунки ракурса сохранены.

## Включение

1. Код включает ранее подготовленные социальные функции (ветка `feat/catalog-social`). Для новой установки сначала выполнить `catalog/supabase.sql`, `catalog/model-geometry.sql`, `catalog/social.sql`. Для существующей установки не повторять начальную схему поверх миграции ниже.
2. В SQL Editor того же проекта Supabase выполнить **`catalog/google-drive/migration.sql`**. Миграция повторяемая, не удаляет строки или файлы. Она разрешает ссылки Google Диска и WebP в существующих полях `stl_path`/`cover_path`.
3. Создать проект на https://script.google.com/ под Google-аккаунтом, имеющим доступ к папке `1ZLyfOh_iJ-qmSKeU9YsA4g6rw-fTDIi1`. Вставить целиком `Code.gs`.
4. В **Project Settings → Script Properties** добавить `SUPABASE_URL` и `SUPABASE_ANON_KEY` из начала `catalog/script.js`. Это URL и публичный anon/publishable key того же проекта. **Не использовать service_role или secret key.** Пользователи проходят проверку access token через `/auth/v1/user`, требуется подтверждённый email.
5. **Deploy → New deployment → Web app**: Execute as **Me**, Who has access **Anyone**. Подтвердить доступ к Drive и внешним запросам. Если администратор Workspace запрещает публичные Web Apps или доступ по ссылке к файлам, такая схема не заработает без изменения ограничений.
6. Скопировать URL вида `https://script.google.com/macros/s/…/exec` в самую первую строку `catalog/script.js`: `const GOOGLE_DRIVE_UPLOAD_URL = '…';`. `/dev` не подходит. Обновить deployment Apps Script при изменении Code.gs.
7. Опубликовать файлы каталога. Проверить с вошедшим пользователем маленький STL: загрузку, просмотр в приватном окне без Google-входа, скачивание, замену STL, пакет из двух файлов, удаление. До заполнения URL новые облачные STL не загружаются; прежние модели и локальное демо доступны.

## Протокол

POST `Content-Type: text/plain;charset=utf-8`; тело JSON:

```json
{"action":"upload","requestId":"UUID","modelId":"UUID","accessToken":"SUPABASE_USER_ACCESS_TOKEN","name":"part.stl","base64":"…"}
```

Ответ: `{ok:true,fileId,name,size,viewUrl,downloadUrl,readUrl}`. При ошибке: `{ok:false,error}` (ContentService может вернуть HTTP 200 и при прикладной ошибке).

POST удаления: `{action:'delete',requestId:'UUID',accessToken:'…',fileId:'…'}`. Удаляется только файл из целевой папки с серверной меткой текущего владельца; ещё опубликованную ссылку сначала нужно заменить или установить `models.deleting=true`. `setTrashed(true)` отправляет файл в корзину.

GET `?id=FILE_ID` → `{ok:true,base64,name,…}` только для опубликованной модели. Секреты и токены в GET не передаются. При блокировке чтения fetch используется read-only JSONP с проверенным именем callback. Apps Script ContentService перенаправляет запрос на `script.googleusercontent.com` и не предоставляет произвольных HTTP CORS-заголовков. Поэтому нельзя добавлять выдуманный `setHeader` или считать `mode:no-cors` успешной загрузкой.

Если POST выполнился, но ответ недоступен, клиент читает квитанцию `?action=status&requestId=UUID` через JSONP. Записывающий POST не повторяется автоматически. Квитанции живут в CacheService до 6 часов и могут быть вытеснены раньше. Если результат так и не подтвердился, пользователь получает сообщение проверить папку; автоматической повторной загрузки нет. Имя физического файла содержит владельца и requestId для защиты от дублей одного запроса. Оригинальное имя хранится в описании файла и используется интерфейсом.

## Существующие файлы и пределы проверки

Это переключение **новых загрузок**, не автоматический перенос старых данных. Прежние STL/PNG в Supabase продолжают работать. При замене STL старый файл удаляется после сохранения новой ссылки. Для освобождения всего старого места нужен отдельный перенос: скачать каждый старый STL, загрузить через новый механизм, сохранить новую ссылку, проверить чтение и только после этого удалить исходник. Нельзя удалять старые объекты до проверки.

Apps Script имеет квоты и ограничения времени, Google Диск — квоты места/раздачи; Base64 увеличивает объём передачи примерно на треть. Пакет до 50 STL обрабатывается последовательно, каждый файл до 20 МБ. Успешная проверка на mock-сервисах не заменяет проверку с вашим deployment URL: он ещё не предоставлен.

Документация: https://developers.google.com/apps-script/guides/content и https://developers.google.com/apps-script/guides/web.
